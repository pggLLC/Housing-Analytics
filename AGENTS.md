# AGENTS.md — Housing-Analytics

Instructions for AI coding agents (OpenAI Codex, GitHub Copilot coding agent, Claude) working in this repo. Both Codex and Copilot read this file automatically; `.github/copilot-instructions.md` (the 18 governance rules) remains authoritative and this file defers to it on data-integrity matters.

## What this repo is
A public-interest **static site** for Colorado affordable-housing data, deployed on **GitHub Pages** (custom domain `cohoanalytics.com` via CNAME). No bundler — client JS attaches to `window.*` via hand-ordered `<script>` tags. Build/fetch scripts are `.mjs` + Python; most workflows are crons that fetch data and commit it back. Exact counts live in the CI-enforced inventory line below — read them there, not from prose.

## Agent pipeline (stay in your lane)
- **Claude** — strategic planning + QA. Owns the remediation plan; reviews every agent PR against it before merge.
- **Codex** — implementation. Executes the phased remediation script; one PR per phase.
- **Copilot** — review. Reviews Codex PRs (automated first pass); also honors this file.

**No two agents edit the same branch/files in the same window.** Implementation happens on branches, never on `main`.

## Hard constraints (do not violate)
1. **Keep the configured developer gate.** The password check in `js/developer-gate.js` is *intentional* UI gating for `/developer*` pages, held in place until Cloudflare Access replaces it — it is a deliberate owner decision, not an oversight or a leaked credential. Do **not** delete the gate or its hash, and do not "helpfully" remove it as a security finding. You may remove the *plaintext password from comments and docs* — that is the only change allowed here. (Background lives in `internal/docs/codex-audits/PASTE-INTO-CODEX.md`, which is intentionally **not** tracked in this repo; you will not find it in a clone, and you do not need it — this rule is complete on its own.)
2. **Obey `.github/copilot-instructions.md` (18 rules).** In particular: Colorado county FIPS are 5-digit strings (`"08001"`); any statewide file carries all **64** counties; required numeric fields are never null; `baseYear`/`pyramidYear` = `2024`.
3. **On ANY change to `data/` or the file inventory:** run `python scripts/rebuild_manifest.py` **and** `node scripts/validate-schemas.js` before committing, or CI fails. This is not optional — Sprint 3 (data architecture) touches data heavily.
4. **Branch + PR only.** Never push to `main`. Never merge your own PR. Open the PR and stop for human/Claude review.
5. **Prefer relocation over deletion.** Before moving or removing any file (esp. under `docs/` or `data/`), `grep` the repo **including `.github/workflows/`** for references — several workflows read from `docs/` (`docs-sync.yml`, the audit pipeline). Don't break a workflow.

## Traps that will hand you a red CI
- **Place pages do not auto-regenerate.** Edit the template in `scripts/hna/build_place_pages.py` and rerun it — never hand-edit `places/*.html`, or `test:place-pages-fresh` fails.
- **`ranking-index` and `ranking-scenarios` are coupled.** Regenerating the index without rebuilding scenarios fails `ci-checks` on the pinned `generatedAt`.
- **Brief ownership sections are auto-generated mid-suite.** A brief failure that appears only under full `test:ci` (and passes in isolation) is real, not a flake.
- **A PR failing on files it never touched** usually means `main` broke after you branched. Rebase before debugging your own diff.
- **`CLEAN` / `MERGEABLE` does not mean CI passed.** Draft PRs never run `ci-checks`, and any commit carrying `[skip ci]` (every data cron does) skips it too. Read the individual check list and confirm `ci-checks` actually appears — not `mergeStateStatus`. Two PRs merged on 2026-08-16 broke `main` exactly this way.
- **`npm test` rewrites tracked files while it runs.** It deletes and regenerates all ~480 files under `data/hna/jurisdiction-metrics-digest/` and rewrites several `data/jurisdiction-briefs/*.json` in place. Mid-run `git status` looks like catastrophic data loss. It self-restores — do not "recover" those files and do not commit them. After the run: `git checkout -- data/`.
- **`npm run test:briefs` is only the Python validator.** It does not cover `test/jurisdiction-brief-metric-digest-sections.test.mjs`. If you change brief wording, run the full `npm test` — the targeted script passing is not evidence. This gap shipped a broken `main`.
- **Rebuild `data/manifest.json` only on a clean tree.** `scripts/rebuild_manifest.py` walks the **filesystem**, not git. This repo lives under an iCloud-synced directory that accumulates untracked duplicates (`08001 2.json`, `08001 3.json`, …); rebuilding with those present inflated the manifest from 1,607 to 3,573 entries and fails CI on a fresh clone. A clean `git status` does **not** rule this out — the duplicates are untracked. Rebuild in a throwaway worktree if unsure.
- **Never `git stash pop` here.** Dozens of worktrees share one stash stack, and a failed `git stash push <path>` still lets a chained `pop` apply another session's stash into `data/`. Copy the file to `/tmp` instead.
- **Do not merge to `main` while a long data build is running.** `build-hna-data.yml` runs ~36 minutes and rebases its data commit at the end; a merge touching `data/manifest.json` inside that window kills the whole run with a rebase conflict. Check for in-flight runs before merging.
